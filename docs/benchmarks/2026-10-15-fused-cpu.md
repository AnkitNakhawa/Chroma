# Fused CPU source benchmark — 2026-10-15

This checkpoint compares the authoritative fused source-layer kernel with the pre-change
materializing CPU renderer. It is a local Apple M3 Pro Release measurement, not a general
performance claim. Eight runs of each variant were alternated in one session; every run rendered
and encoded 120 frames at 640×360.

The benchmark composition is generated as
`build-release/benchmarks/fused-video-composition.json`. It applies one fractional affine
transform, a crop, and opacity to a decoded video before source-over compositing. The fused path
samples, applies the pointwise operation, and composites in one loop, avoiding the one
canvas-sized transform output used by the reference path.

| Variant | Samples | Throughput | Mean total | Mean execution |
|---|---:|---:|---:|---:|
| Fused CPU | 8 | 231.3 fps | 518.91 ms | 322.69 ms |
| Pre-change reference | 8 | 212.3 fps | 565.30 ms | 363.82 ms |

On this workload, fusion improved throughput by 8.9%, reduced total time by 8.2%, and reduced
execution time by 11.3%. Pixel-equivalence tests compare the transformed fused kernel with the
explicit reference mode exactly for fractional and singular transforms, crop, opacity, and all
four blend modes. Separate fallback tests cover scaled placement, color matrices, and unsafe
effect ordering.

The profitability investigation also found negative cases. Adding a color matrix made the first
fused implementation about 5.6% slower for a transformed workload and about 10.8% slower for a
scaled workload. A large scaled-placement-plus-opacity case improved only about 0.8%, while
fusing the small scaled image in the basic-graphics fixture regressed that representative
workload. The default gate therefore leaves color matrices, placement scaling, and native-copy
operations on the reference path.

The unchanged video corpus remains a regression control because it has no avoidable placement or
transform intermediate and therefore stays on the reference path. In a final alternating
six-sample control it measured 255.9 fps with the new build and 256.3 fps with the pre-change
build, effectively flat (-0.2%). The 160×90 combined basic-graphics fixture also stays on the
reference path; a separately built pre-change binary was about 3.2% faster in a 12-sample
alternating local run (1,271.6 vs 1,231.2 fps). No fused operation ran in that fixture, so this is
reported as a build/code-layout regression signal rather than attributed to avoided work.

The separate YUV → RGBA8 →
linear-float → RGB8 → YUV pipeline is unchanged. Removing that chain requires a codec/color
surface residency design and is the next major performance boundary, not a safe extension of this
CPU kernel.
